# 架构

## 目标

实现可重放、可恢复、不可由客户端伪造结算结果的两人回合制卡牌对战。第一阶段优先保证规则清晰、事件模型稳定和本地端到端联通，再增加账号、持久化、观战和匹配质量。

## 组件

```text
Godot C# Client
  ├─ Presentation
  │    └─ 渲染 MatchView、动画播放 Event[]
  ├─ Client Core
  │    ├─ 协议 DTO
  │    ├─ 连接与会话状态
  │    └─ 事件日志和断线补帧入口
  └─ Godot Adapter
       └─ WebSocketPeer + Node 生命周期

WebSocket JSON
  ↓
Go Server
  ├─ transport/ws
  │    └─ 连接、读写、消息大小限制、ping/pong
  ├─ match
  │    ├─ 队列与配桌
  │    ├─ 房间串行化
  │    └─ 按玩家广播事件和投影
  ├─ game
  │    ├─ 规则校验
  │    ├─ 权威状态
  │    ├─ 事件生成
  │    └─ 按座位裁剪视图
  └─ protocol
       └─ 线协议 DTO、错误码、版本
```

## 数据流

1. 客户端发送带 `commandId` 和 `expectedRevision` 的意图。
2. 房间确认玩家属于该对局，并串行处理指令。
3. `game` 检查回合、费用、目标、手牌、场地和版本号。
4. 拒绝时返回 `match.command_result(accepted=false)`，状态与修订号不变。
5. 接受时服务端修改权威状态，递增 `revision`，生成连续 `seq` 事件。
6. 房间把事件按玩家可见性过滤，并附上该玩家可用的最新 `MatchView`。
7. 客户端先应用事件用于日志和动画，再以同一个 `MatchView` 校正 UI。

## 权威状态

权威状态只存在于 Go 服务的房间内存中。它包含双方牌库顺序、手牌、英雄血量、费用、场地单位、回合信息、随机源、当前修订号和最后事件序号。

`MatchView` 是权威状态的单向投影，不是可回写模型。对手手牌和牌库只暴露数量，不暴露实例 ID、卡牌 ID 或顺序。客户端任何本地状态都必须视为缓存。

## 事件与修订号

- `revision`：每接受一个玩家指令递增一次。
- `seq`：每条事件全局递增，事件序号在房间生命周期内连续。
- 一个指令可以产生零到多条事件；接受但零事件时仍只递增 `revision`。
- 被拒绝指令不产生领域事件，不改变 `revision` 或 `seq`。
- 房间保存完整事件日志；玩家广播使用按座位过滤后的日志。

## 回放

回放有两种视图：

- 玩家回放：只包含该玩家当时可见的信息。
- 服务端审计回放：包含完整状态变化，仅服务端或授权后台可读取。

当前阶段先生成不回放 UI 的事件日志。后续断线恢复流程为：

1. 客户端发送 `match.resume`，携带玩家凭证和 `lastEventSeq`。
2. 服务端校验房间、座位和凭证。
3. 服务端返回最新 `MatchView` 和 `lastEventSeq` 之后的事件。
4. 客户端清空旧缓存，以快照为准，再顺序播放缺失事件。

## 确定性与随机

- 洗牌、先手和随机效果只在服务端执行。
- 房间保存随机种子和完整事件；回放以事件为准，不依赖客户端重跑随机数。
- 规则实现不得读取系统时间、进程状态或未注入的全局随机源。
- 未来若调整随机算法，必须保留旧房间的算法版本。

## 并发模型

- 每个 WebSocket 连接有一个读循环和一个写循环。
- 写循环独占 socket，其他组件只向有界发送队列投递消息。
- 每个房间用单锁保护权威状态和事件日志，保证指令串行结算。
- 匹配管理器只保护会话表、等待队列和房间路由，不参与规则计算。
- 慢客户端不得阻塞房间结算；发送队列满时关闭该连接并记录。

## 失败处理

- 非法消息：返回 `error`，必要时关闭连接。
- 版本过期：返回 `stale_revision`，客户端等待或请求恢复。
- 非法指令：返回 `invalid_command`，不断开正常对局。
- 服务端内部错误：返回 `internal_error`，保留日志和请求 ID。
- MVP 断线：按认输处理；可靠重连在持久化和凭证完成后启用。

## 安全边界

- 客户端显示内容永远不能作为合法性依据。
- 不在客户端下发对手隐藏区域内容。
- WebSocket 消息设置大小上限，JSON 解码拒绝未知关键字段。
- 所有卡牌目标都使用实例 ID，不使用 UI 索引。
- 日志不记录玩家令牌、完整原始消息中的敏感字段。
