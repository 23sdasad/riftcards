## 目标与背景

项目更名后，工程路径、命令入口、Go import、C# 项目和协议到引擎的数据路径已经统一，但跨平台路径语义和“哪些路径是权威入口、允许依赖哪些方向、状态如何从网络走到规则再回到客户端”仍分散在多份文档和代码约定中。本任务建立可复用的跨平台 path 能力和路径边界基线，供后续 shell、状态机和指令链路任务共同引用。

## 必读

[架构总览](../architecture/overview.md) · [工程约定](../architecture/conventions.md) · [协议](../contracts/protocol.md) · [技术栈](../contracts/tech-stack.md) · [测试策略](../architecture/testing.md)。

## 范围与非目标

交付：

- 建立 Windows、macOS、Linux 共用的路径语义，至少覆盖分隔符、绝对/相对路径、驱动器/UNC 差异、用户目录、可执行文件后缀和大小写差异。
- 提供可复用的 path 基础实现或明确采用的标准库边界；禁止业务代码手工拼接平台路径。
- 用表驱动或跨平台测试覆盖路径解析、拼接、规范化、比较和越界/非法输入。
- 新增路径与边界主题文档，列出仓库路径、构建入口、协议路径和依赖方向。
- 明确“意图如何到达权威状态”和“事件/投影如何回到客户端”的单向路径。
- 标记禁止路径，例如客户端最终结算、协议层调用网络、规则层依赖 Godot。
- 把现有 README、架构索引和 task 中的路径引用指向该文档，消除重复维护。

非目标：

- 不改变协议语义、游戏规则或 Godot 表现。
- 不新增 shell 命令；环境检查由 004 处理。
- 不为潜在模块预建空目录。

## 前置条件与待决策

- `path` 已确认同时覆盖工程路径和指令路径，并以 Windows、macOS、Linux 为支持目标。
