# 016 — Godot 界面可用性与视觉整理

- 状态：in-progress
- 依赖：008、009
- 优先级：P1
- 创建 / 更新：2026-10-11 / 2026-10-11

## 目标与背景

008 交付的对局界面功能完整（出牌、选目标、攻击、结束回合、认输、错误提示），但它是"最小可用交互"，从未被渲染检查过：此前误判本机无显示环境，只跑过 headless。实际渲染后（1280×800 与 900×480 两张截图）确认了一批肉眼可见的缺陷。本任务按[客户端界面](../architecture/client-ui.md)实现布局与视觉约定，并修掉这些缺陷。

## 已确认的缺陷（截图证据）

| # | 缺陷 | 说明 |
| --- | --- | --- |
| 1 | `场地` 标签位置错误 | 被加在"结束回合/认输"按钮之后，看起来像在标注按钮 |
| 2 | 对手英雄按钮横跨整屏 | "选择攻击者后可攻击"是一条全宽禁用按钮，像误入的灰条 |
| 3 | 大窗口中间大片空白 | `ScrollContainer` 把事件面板顶到底部，浪费约 250px |
| 4 | 事件日志是原始 JSON | `{"attack":1,"cardId":"shield_bearer"}`，不是给人看的文本 |
| 5 | 终局提示错误 | 对局已 `finished` 时提示行仍写"等待对手行动。" |
| 6 | 缺少胜负反馈 | 英雄 HP 0 时没有任何横幅或强调 |
| 7 | 小窗口操作掉出首屏 | 900×480 时自己的手牌与"结束回合"完全不可见（008 的该验收项因此判定为不合格） |

## 范围与非目标

交付：

- 按 `client-ui.md` 实现：对手在上/自己在下、回合条居中、手牌与场地横向滚动、事件面板可折叠且固定小高度。
- 程序化主题：颜色、字号、面板样式、状态色（生命/回合/守卫/选中/拒绝）。
- 组件重做：`HeroPanel`、`UnitButton`、`CardButton`、`TurnBar`、`HintLine`、`TerminalBanner`。
- 事件文本可读化（事件类型 + 载荷 → 中文句子），未知类型标注忽略。
- 修掉上表 7 条缺陷，尤其是"结束回合必须在首屏"。

非目标：

- 不引入美术资源、音效、动画队列（动画队列由 009 的接口承载，本任务只改文本表现）。
- 不改协议、规则或 Core 边界；界面仍不计算费用、伤害、目标合法性或胜负。
- 不引入 `.tscn` 场景与 `.tres` 主题资源（保持代码构建，便于编译与测试覆盖）。

## 决策与工作记录

- 2026-10-11：创建任务。起因是首次真实渲染后发现 008 的界面存在可见缺陷，且"无显示环境"是错误结论。
- 2026-10-11：界面继续用代码构建而非 `.tscn`：可被编译器与单元测试覆盖，且不需要美术资源即可迭代；视觉约定集中在 `UiTheme`，将来换主题资源只改一处。
- 2026-10-11：不做费用可用性着色：那需要客户端计算费用合法性，违反 008 的边界；费用不足由服务端拒绝并显示错误码。
- 2026-10-11：第一次实现后 900×480 截图显示手牌与回合条仍在折叠线以下（战场整块可滚动导致操作被推下去）。改为**只有战场在滚动区**、手牌与回合条固定底部，并在窗口高度 < 620px 时自动折叠事件面板；这样两种尺寸都满足"操作在首屏"。
- 2026-10-11：1280×800 首版把己方场地行裁到一半（纵向空间不够）。收紧尺寸（事件面板 130→96、卡牌 56→52、单位 52→48、区块间距 10→8）并把英雄面板从两行压成单行后，两种尺寸都不再裁切。
- 2026-10-11：生命值不做比例着色：投影里 `PlayerView` 只有 `hp`，没有最大生命；按比例着色需要客户端复制规则常量，因此只在 `HP 0`（阵亡）时标红，并把"补 `maxHealth`"记为协议侧的后续可选项。
- 2026-10-11：为了能反复验证界面，客户端新增开发参数 `--screenshot=`/`--screenshot-delay=`（按真实时间计时）与 `--smoke-autoplay`（走与点击相同的意图路径），截图工具留在仓库里而不是一次性脚本。
