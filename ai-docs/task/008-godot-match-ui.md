# 008 — Godot 对局界面纵切

- 状态：planned
- 依赖：007
- 优先级：P1
- 创建 / 更新：2026-10-08 / 2026-10-08

## 目标与背景

当前 Godot 客户端是单文件诊断页，自动替玩家选择法术和攻击目标，无法完成真实局部操作。本任务把 `MatchView` 变成可操作的本地对局界面，同时保持所有规则判断在服务端。

## 必读

[游戏规则](../product/game-rules.md) · [协议](../contracts/protocol.md) · [架构总览](../architecture/overview.md) · [规则与协议验证基线](007-rule-protocol-validation.md)。

## 范围与非目标

交付：

- 拆分应用壳、对局视图和可复用 UI 组件，不再把全部逻辑堆在 `Main.cs`。
- 展示双方英雄、手牌、牌库数量、费用、场地单位、回合和连接状态。
- 支持点击卡牌和合法目标、点击单位攻击、结束回合和认输。
- 根据 `MatchView` 禁用非法操作，并展示服务端错误码与可读提示。
- 保证 UI 不计算伤害、费用、目标合法性或胜负。

非目标：

- 不实现动画队列；由 009 处理。
- 不引入正式美术、音效或客户端预测。
- 不改变协议和规则。

## 前置条件与待决策

- 依赖 007 的稳定投影和协议样例。
- 需要确认界面是功能优先的开发版棋盘还是同时确定视觉方向；未确认前只做最小可用交互。
- Godot 项目路径和进程启动必须遵循 003/004 的跨平台约束。

## 实施步骤

1. 把诊断界面拆成应用壳、对局面板和卡牌/单位组件。
2. 建立纯 C# 视图模型，把协议投影转换成可绑定状态。
3. 实现卡牌、目标、攻击、结束回合和认输交互。
4. 显示服务端错误，并在快照校正后清理无效选择。
5. 用一个真实服务端和两个客户端完成手工本地对局冒烟。

## 预计改动

- 修改：`client/src/Main.cs`、`client/scenes/Main.tscn`。

- 修改：客户端运行说明。

## 清理与兼容例外

删除自动选目标、诊断按钮堆叠和规则判断式 UI 逻辑。无协议兼容例外。

## 验收标准

- [ ] 玩家能通过 UI 完成出牌、选目标、攻击、结束回合和认输。
- [ ] 非法操作由服务端拒绝，UI 只展示错误并回到有效快照。
- [ ] 对手手牌和牌库内容不进入 UI 或客户端缓存。
- [ ] 窗口缩放后核心操作仍可见，不因动态文本重叠。
- [ ] Godot 与纯 .NET 构建、测试通过，并完成本地冒烟记录。

## 风险与回退

主要风险是把规则判断或目标自动选择写进 UI，形成第二套权威逻辑。回退时恢复诊断界面，保留纯视图模型和组件拆分，不改变服务端。
