## 目标与背景

Phase 1 完成标准是本地完整对局可运行、可观察、可重复验证。现有任务分别验证规则、UI 和事件表现，但缺少真实 WebSocket、房间串行化、两个会话和最终胜负的联合验收。

## 范围与非目标

交付：

- 一个可重复的本地端到端测试：启动真实 Go 服务，两个独立 WebSocket 客户端完成一整局。
- 固定随机种子或测试房间入口，使首批事件和胜负路径可复现。
- 断言双方投影、隐藏信息、`revision`、`seq`、终局事件和连接关闭行为。
- 增加结构化连接/房间日志与最小运行时指标，足以定位卡住或断线。
- 使用真实 Godot 客户端完成一次手工双端冒烟。

非目标：

- 不做断线恢复、凭证、幂等命令和持久化。
- 不要求正式发布打包。
- 不用客户端 UI 状态推导服务端回放结果。

## 前置条件与待决策

- 依赖 007 的合同样例、008 的对局 UI 和 009 的表现队列。
- 测试入口必须跨平台，不能依赖 POSIX shell、固定端口残留或等待超时猜测。
- 若新增测试专用种子/房间入口，必须隔离于生产默认路径并记录安全边界。

## 实施步骤

1. 定义固定脚本的一局对局和预期关键事件。
2. 启动真实服务进程，使用跨平台 shell 能力管理生命周期和端口。
3. 建立两个独立协议客户端，按回合提交命令并校验投影。
4. 断言事件序号、修订号、隐藏信息和终局结果。
5. 运行真实 Godot 双客户端手工冒烟并记录日志。
6. 在 Windows、macOS、Linux 运行可用门禁。

## 预计改动

- 新增：端到端测试、测试房间或固定种子入口、测试客户端辅助代码。
- 修改：服务端启动参数、结构化日志和指标接入点。
- 修改：测试策略、README 和协议运行说明。

## 清理与兼容例外

删除依赖固定宿主机路径、残留进程和人工观察才能判断结果的验收步骤。测试专用入口不得绕过权威结算。

## 验收标准

- [ ] 一条命令启动服务并让两个独立客户端完成一局。
- [ ] 测试对关键事件顺序、投影裁剪、版本和最终胜负有明确断言。
- [ ] 固定种子测试可复现，随机失败可定位到请求、修订号和事件序号。
- [ ] 测试结束后服务、连接和子进程全部退出，无孤儿进程。
- [ ] 真实 Godot 双客户端冒烟完成并记录限制。

## 风险与回退

风险是把端到端测试写成依赖时间、端口和外部进程的脆弱脚本。回退时缩小为服务端加两个协议客户端的自动测试，Godot 冒烟保留为人工证据。
