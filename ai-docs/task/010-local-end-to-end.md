## 目标与背景

Phase 1 完成标准是本地完整对局可运行、可观察、可重复验证。现有任务分别验证规则、UI 和事件表现，但缺少真实 WebSocket、房间串行化、两个会话和最终胜负的联合验收。拉起服务端与客户端进程使用 [004](004-shell-run-entry.md) 的 `platform/proc`。

## 范围与非目标

交付：

- 一个可重复的本地端到端测试：启动真实 Go 服务，两个独立 WebSocket 客户端完成一整局。
- 固定随机种子或测试房间入口，使首批事件和胜负路径可复现。
- 断言双方投影、隐藏信息、`revision`、`seq`、终局事件和连接关闭行为。
- 增加结构化连接/房间日志与最小运行时指标，足以定位卡住或断线。
- 使用真实 Godot 客户端完成一次手工双端冒烟。

非目标：

- 不做断线恢复、凭证、幂等命令和持久化。
- 不要求正式发布打包。
- 不用客户端 UI 状态推导服务端回放结果。

## 前置条件与待决策

- 依赖 007 的合同样例、008 的对局 UI 和 009 的表现队列。
- 测试入口必须跨平台，不能依赖 POSIX shell、固定端口残留或等待超时猜测。
- 若新增测试专用种子/房间入口，必须隔离于生产默认路径并记录安全边界。

## 实施步骤

1. 定义固定脚本的一局对局和预期关键事件。
2. 启动真实服务进程，使用跨平台 shell 能力管理生命周期和端口。
3. 建立两个独立协议客户端，按回合提交命令并校验投影。
4. 断言事件序号、修订号、隐藏信息和终局结果。
5. 运行真实 Godot 双客户端手工冒烟并记录日志。
6. 在 Windows、macOS、Linux 运行可用门禁。

## 验收标准

- [x] 一条命令启动服务并让两个独立客户端完成一局：`go -C server test ./internal/e2e`（`task ci` 已包含）。
- [x] 测试对关键事件顺序、投影裁剪、版本和最终胜负有明确断言（事件并集精确覆盖 `1..lastEventSeq`、接受路径 `revision` 恰好 +1、对手手牌内容从不出现、终局 `winnerSeat` 双方一致、拒绝错误码都在文档清单内）。
- [x] 固定种子测试可复现，随机失败可定位到请求、修订号和事件序号（失败输出包含每个客户端的 `requestId`/`commandId`/指令/接受与否/`revision`/错误码、投影、回合进度与服务端日志）。
- [x] 测试结束后服务、连接和子进程全部退出，无孤儿进程（`proc` 终止进程树 + 断言进程已退出且 `/healthz` 不再响应）。
- [x] 真实 Godot 双客户端冒烟完成并记录限制（无显示器环境，用 `--server=` 自动连接的无界面双客户端冒烟；人工点击与视觉检查未执行）。

## 风险与回退

风险是把端到端测试写成依赖时间、端口和外部进程的脆弱脚本。回退时缩小为服务端加两个协议客户端的自动测试，Godot 冒烟保留为人工证据。

## 决策与工作记录

- 2026-10-08：创建任务。端到端验收放在规则、UI 和事件队列之后，作为 Phase 1 完成门槛。
- 2026-10-08：固定种子用服务端 `-seed` 参数实现，边界写进 README 与架构安全边界：只用于本地测试，生产保持每局随机，否则先手与牌序可被预测。测试专用入口不绕过权威结算——客户端仍然只发意图。
- 2026-10-08：端口不用猜：服务端改为先 `net.Listen` 再 `Serve`，把解析后的真实地址写进结构化日志；测试传 `-addr 127.0.0.1:0` 并从日志读取地址，因此不会因固定端口残留而失败。
- 2026-10-08：新增最小指标（连接、对局、接受/拒绝指令、事件数、广播数）与 `/metrics` 文本端点，并在端到端测试里断言计数与实际结算一致，使“足以定位卡住或断线”可被验证而不是只靠人工观察。
- 2026-10-08：端到端测试客户端遵守三条纪律：同一时刻只允许一条在途指令（否则响应与请求交错）、被接受的指令要等投影追平（拒绝不推进版本，去等会永久卡住）、终局快照到达即结束脚本（服务端不会再主动发消息）。
- 2026-10-08：发现并记录一个协议使用要点：拒绝结果里的 `revision` 是**服务端处理该请求时**的版本，可能落后于客户端已看到的最新投影（两个客户端的响应流彼此独立）。客户端不得据此判断“状态回退”，投影单调性才是判据。
- 2026-10-08：`server/internal/e2e` 随 `task ci` 在三平台执行，因此 Phase 1 的验收门槛进入常规门禁，而不是一次性人工步骤。

## 完成摘要

建立了可重复的本地端到端验收：`server/internal/e2e` 用 `platform/proc` 编译并启动真实服务进程（`-addr 127.0.0.1:0`，从结构化日志读取真实地址），两个独立协议客户端只依据投影决策完成一整局（出牌、选目标、攻击、结束回合），并故意提交一次越权指令验证拒绝路径。

断言覆盖：两个客户端进入同一对局且座位为 0/1；事件并集精确覆盖 `1..lastEventSeq`（按座位过滤不丢不重）；对手手牌内容从不进入任何投影；接受路径 `revision` 恰好 +1；终局 `status` 与 `winnerSeat` 双方一致；`match_ended` 带结束原因；所有拒绝错误码都在协议文档清单内；`/metrics` 计数与实际结算一致；测试结束后服务进程退出、`/healthz` 不再响应。固定种子下两局的事件序列逐字节一致。

可观测性：`match`/`ws` 接入结构化日志（连接、会话、排队、建房含种子、接受/拒绝含 commandId 与版本、认输、断开），新增 `internal/metrics` 与 `GET /metrics`。端到端测试随 `task ci` 在三平台执行（run 38121392505：ubuntu 2m28s、windows 4m22s、macos 3m54s）。Phase 1 的路线图条目全部完成。

限制：本机无显示环境，Godot 侧只做了无界面双客户端冒烟（自动连接 + 自动结束一回合），人工点击与视觉检查未执行。
