- [x] 游戏规则初稿

- [x] 第三方库调研

## Phase 1：本地完整对局

- [ ] 补齐 8 张 MVP 卡牌的引擎实现和测试

- [ ] 增加事件动画队列和错误提示
- [ ] 增加服务端和客户端协议的固定样例测试

## Phase 2：可靠连接

- [ ] 断线宽限期与超时认输

## Phase 3：产品化

- [ ] 账号和匹配评级
- [ ] 数据库存储对局、卡组和审计日志
- [ ] 观战和公开回放
- [ ] 指标、追踪和告警
- [ ] 内容版本与规则版本迁移

## 暂缓事项

- 客户端权威预测：可以改善手感，但必须保留服务端回滚。
- Protobuf/FlatBuffers：只有在 JSON 性能或带宽成为瓶颈时迁移。
- ECS：当前卡牌状态规模小，显式领域模型更易验证。
- 微服务：单进程模块化足以支撑 MVP。
